# IEP GEN Dev Plan (MVP รอบส่งใบสมัคร)

เอกสารนี้สำหรับทีม dev 2 คน อ่านให้เข้าใจตรงกันก่อนเริ่มโค้ด

## 1. เป้าหมายรอบนี้ — อ่านตรงนี้ก่อนทุกอย่าง

**สิ่งที่ต้องได้เมื่อจบโปรเจกต์นี้:**
1. ระบบที่ deploy ขึ้นเว็บจริง
2. แผน IEP ที่สร้างจากระบบของเรา
3. ตัวเลขเวลา before/after ที่จับจริง
4. รายการทุกจุดที่ user แก้ output ของ AI (= insight ที่ทีมอื่นไม่มี)

## 2. Solution คืออะไร (สรุปสั้น)

ครูกรอกข้อมูลเด็กแบบเลือกจากตัวเลือก (dropdown/checklist ไม่ต้องพิมพ์ prompt)
→ ระบบค้นข้อมูลที่ถูกต้องจาก mapping table
→ ส่งให้ LLM เรียบเรียงเป็นภาษาเอกสารราชการ
→ ครูได้เป้าหมาย IEP + รายการสื่อที่เบิกได้ + เหตุผลประกอบ

## 3. MVP Scope — ทำแค่นี้ ห้ามเกิน

### ✅ ต้องมี (Must have)

- [ ] หน้ากรอกโปรไฟล์เด็ก — **เฉพาะประเภทความพิการที่แม่ต้องใช้จริงสิ้นเดือนนี้** (ยังไม่ต้องครบ 9 ประเภท)
- [ ] Generate เป้าหมาย IEP — เสนอ 2-3 ตัวเลือกให้ครูเลือก
- [ ] Generate รายการสื่อ/บัญชี ก-ข + เหตุผลประกอบ
- [ ] **ปุ่ม Copy ข้อความ** ทุกช่อง (ให้แม่วางเข้าระบบ SET ได้ทันที)
- [ ] แก้ไขข้อความที่ AI สร้างได้ (textarea ธรรมดาก็พอ)
- [ ] Deploy ขึ้นเว็บจริง (Vercel)

### ⏸️ ทำถ้าเวลาเหลือ (Nice to have)

- [ ] IIP (วิธีสอน)
- [ ] ปุ่ม Regenerate เมื่อแก้ข้อมูลโปรไฟล์
- [ ] Consistency check พื้นฐาน
- [ ] เพิ่มประเภทความพิการอื่น

### ❌ ไม่ทำรอบนี้ (ตัดทิ้ง)

- ระบบ login / user account
- Database (ใช้ JSON file ใน repo พอ)
- Export PDF/Word สวยงาม
- Dashboard ผู้บริหาร
- เชื่อมต่อ API ระบบ SET จริง
- Mobile responsive แบบสมบูรณ์ (แค่ใช้ได้บนคอมพอ)

## 4. Tech Stack

```
Framework : Next.js (App Router) — frontend + API route ในโปรเจกต์เดียว
Styling   : Tailwind CSS
AI        : Claude API หรือ OpenAI API (เรียกจาก API route ฝั่ง server เท่านั้น)
Data      : JSON file ใน repo (mapping table + few-shot examples)
Deploy    : Vercel (auto deploy จาก main branch)
Repo      : GitHub (private)
```

**ทำไมเลือกแบบนี้:** ไม่ต้องแยก backend server, deploy ได้ใน 5 นาที, แม่เปิดใช้ได้จากทุกที่โดยไม่ต้องติดตั้งอะไร

> ⚠️ **API key ต้องอยู่ฝั่ง server เท่านั้น** (ใน API route) ห้ามใส่ใน client code เด็ดขาด

## 5. Data Contract — ตกลงกันก่อนแยกไปทำ

ทั้งคู่ยึด schema นี้ ใครทำเสร็จก่อนไม่ต้องรออีกคน

### Request (Frontend → API)

```json
POST /api/generate
{
  "disabilityType": "autism",
  "abilityLevels": {
    "communication": "no_speech_gesture_only",
    "behavior": "frequent_off_task",
    "reading": "cannot_spell_2syllable"
  },
  "strengths": "ชอบวาดภาพ จดจำภาพได้ดี",
  "gradeLevel": "ป.2"
}
```

### Response (API → Frontend)

```json
{
  "iepGoals": [
    {
      "id": "goal_1",
      "text": "นักเรียนสามารถใช้บัตรภาพ PECS เพื่อสื่อสารความต้องการพื้นฐาน 3 อย่าง ได้ถูกต้อง 8 ใน 10 ครั้ง ภายในภาคเรียนนี้",
      "criterion": "8 ใน 10 ครั้ง",
      "timeframe": "ภายในภาคเรียนนี้"
    },
    { "id": "goal_2", "text": "...", "criterion": "...", "timeframe": "..." }
  ],
  "mediaRecommendations": [
    {
      "item": "บัตรภาพ PECS",
      "category": "ก",
      "reason": "เนื่องจากนักเรียนยังไม่สามารถสื่อสารด้วยคำพูด การใช้ระบบสื่อสารทางเลือกด้วยภาพจะช่วยให้..."
    }
  ],
  "iipMethods": [
    { "id": "method_1", "text": "...", "linkedGoalId": "goal_1" }
  ]
}
```

**กติกา:** ถ้าต้องแก้ schema นี้ ต้องบอกอีกคนทันที ห้ามแก้เงียบๆ

## 6. แบ่งงาน

### คน A (เจ้าของ domain — คนที่คุยกับแม่ได้)

**ไฟล์ที่รับผิดชอบ:** `/data/*.json`, `/lib/prompts.ts`, `/app/api/generate/route.ts`

- [ ] คุยกับแม่เก็บ requirement (ดูข้อ 7)
- [ ] สร้าง `mappingTable.json` — ระดับความสามารถ → สื่อ/บัญชี ก-ข
- [ ] สร้าง `fewShotExamples.json` — ตัวอย่าง input/output จากแผน IEP จริงของแม่ (ลบชื่อเด็ก)
- [ ] เขียน system prompt + few-shot prompt
- [ ] เขียน API route: รับ request → lookup mapping table → เรียก LLM → return JSON
- [ ] ทดสอบ output กับแม่ ปรับ prompt จนแม่บอกว่า "ใช้ได้"

### คน B (frontend + infra)

**ไฟล์ที่รับผิดชอบ:** `/app/page.tsx`, `/components/*`, Vercel config

- [ ] ตั้ง repo + Next.js + Tailwind + deploy หน้าเปล่าขึ้น Vercel **ให้เสร็จวันแรก**
- [ ] หน้ากรอกโปรไฟล์เด็ก (dropdown/checklist ตาม schema)
- [ ] หน้าแสดงผล: เป้าหมาย IEP (เลือกได้) + รายการสื่อ + เหตุผล
- [ ] ปุ่ม Copy ทุกช่อง + แก้ไขข้อความได้
- [ ] Loading state ระหว่างรอ AI (สำคัญ — ไม่งั้นแม่จะคิดว่าค้าง)
- [ ] Error handling เบื้องต้น (API พัง → แสดงข้อความบอก ไม่ใช่หน้าขาว)

**คน B เริ่มได้ทันทีด้วย mock data** ตาม schema ข้อ 5 ไม่ต้องรอ API เสร็จ

## 7. คำถามที่ต้องถามแม่ก่อนเริ่มโค้ด (สำคัญกว่าเริ่มโค้ด)

1. สิ้นเดือนนี้ต้องทำ IEP ให้เด็กกี่คน แต่ละคนความพิการประเภทไหน
   → **สร้างระบบรองรับเฉพาะประเภทที่แม่ต้องใช้จริง**
2. ตอนนี้เขียนส่วนไหนช้าที่สุด (เป้าหมาย / วิธีสอน / รายการเบิกสื่อ)
   → **ทำส่วนนั้นให้ดีที่สุดก่อน**
3. ขอดูแผน IEP ปีก่อนของเด็ก 2-3 คน (ลบชื่อออก)
   → **ใช้เป็น few-shot examples ที่ตรงกับ format ที่แม่ต้องส่งจริง**
4. ปกติทำ IEP 1 คนใช้เวลาเท่าไหร่
   → **ตัวเลข baseline สำหรับเทียบ before/after**

## 8. กฎเรื่องข้อมูลเด็ก (ห้ามละเมิด)

ข้อมูลเด็กพิเศษ = ข้อมูลอ่อนไหวของผู้เยาว์ ต้องระวังตั้งแต่บรรทัดแรกของโค้ด

- ❌ **ห้ามเก็บชื่อจริงเด็ก** ในระบบ/log/database ใดๆ — ใช้รหัสแทน (เด็ก A, B, C) แม่จำเองว่าใครคือใคร
- ❌ **ห้ามส่งชื่อ อายุ โรงเรียน ไป LLM API** — ส่งเฉพาะประเภทความพิการ + ระดับความสามารถ
- ❌ **ห้าม commit ข้อมูลเด็กจริงขึ้น GitHub** (รวมถึงใน few-shot examples — ต้องลบชื่อก่อน)
- ✅ ถ่ายหน้าจอ/อัดคลิปได้ แต่ต้องปิดข้อมูลระบุตัวตนทั้งหมด

> จุดนี้กลายเป็นจุดแข็งตอน pitch ด้วย — บอกได้ว่า "เราออกแบบ privacy-by-design ตั้งแต่ prototype แรก เพราะทดสอบกับข้อมูลจริง"

## 10. Definition of Done — ถือว่าเสร็จเมื่อ

- [ ] แม่เปิดเว็บจากคอมที่บ้าน/โรงเรียนแล้วใช้ได้ โดยไม่ต้องให้เราช่วย
- [ ] แม่กรอกข้อมูลเด็ก 1 คน แล้วได้เป้าหมาย IEP + รายการสื่อ ที่ **แม่บอกว่าเอาไปใช้ได้จริง**
- [ ] แม่ copy ข้อความไปวางในระบบ SET ได้สำเร็จ
- [ ] เราจับเวลาได้ว่าใช้เวลาเท่าไหร่ เทียบกับเดิม
- [ ] เราบันทึกได้ว่าแม่แก้ output ตรงไหนบ้าง กี่จุด

## 11. สิ่งที่ต้องเก็บระหว่างแม่ใช้งานจริง (อย่าลืม!)

นี่คือของที่จะทำให้ใบสมัครเราแข็งกว่าทีมอื่น — **สำคัญพอๆ กับตัวโค้ด**

1. ⏱️ **จับเวลาจริง** — ก่อนใช้ระบบ vs หลังใช้ระบบ ต่อเด็ก 1 คน
2. 📝 **บันทึกทุกจุดที่แม่แก้ output ของ AI** — ทุกจุดที่แก้ = จุดที่ระบบยังไม่ดีพอ = insight ที่ใช้พูดใน pitch ได้
3. 📸 **ถ่ายหน้าจอ** (ปิดข้อมูลเด็ก) ระหว่างใช้จริง
4. 🎥 **อัดคลิปสั้นตอนแม่ใช้** ถ้าแม่ยินยอม — ใช้ในวิดีโอ demo ได้ทรงพลังมาก
5. 💬 **ถามแม่หลังใช้เสร็จ:** "จะใช้ต่อไหม" / "จะแนะนำเพื่อนครูไหม" ← คำตอบนี้คือ validation ที่แข็งที่สุด

1. **เป้าหมายคือให้แม่ใช้ได้จริงทัน 31 ก.ค.** ไม่ใช่ทำ product สมบูรณ์
2. **สื่อ/บัญชี ก-ข ใช้ mapping table เท่านั้น** ห้ามให้ LLM คิดเอง
3. **เก็บหลักฐานการใช้จริงให้ครบ** สำคัญพอๆ กับตัวโค้ด
